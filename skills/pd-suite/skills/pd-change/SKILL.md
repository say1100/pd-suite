# 变更影响分析与决策记录

两个模式,按用户意图选择(可连用:先分析影响,用户拍板后落 ADR):

| 模式 | 触发语 | 产出 |
|---|---|---|
| **A 影响分析** | "这个功能不做了""改需求了""换成方案 B,影响什么" | `outputs/change-impact-<时间戳>.md` |
| **B 决策记录** | "记一下这个决定""就这么定了" | `outputs/adr/ADR-00N.md` |

## 模式 A|影响分析(步骤见 prompts/steps.md §C1–C4)

1. **C1 定位变更**:变更内容、动机、波及范围(需求/方案/功能/指标/口径哪一层)。
2. **C2 扫描关联**:遍历工作区 `outputs/` 既有产物(requirements/tradeoff/demo 产物/eval-plan),逐份标注"受影响/不受影响"及理由。
3. **C3 影响分级**:🔴 需重做(产物核心假设被推翻)/ 🟡 需重验(改几处后重跑评测)/ 🟢 无需动。
4. **C4 变更单**:变更内容 → 影响清单(按产物列) → 建议动作 → 回归范围(哪些评测要重跑)。

## 模式 B|ADR 决策记录

1. 用户拍板后,写 `outputs/adr/ADR-00N.md`(编号递增,不重复使用)。
2. ADR 结构:编号/日期/状态(已采纳/已废弃)/背景/决策/理由/备选方案/后果与影响(链接变更单)。
3. **铁律**:ADR 只追加不改写;决策被推翻时新增 ADR 并把旧的标"已废弃(被 ADR-00M 取代)"。

## 铁律

- **不修改历史产物**:变更产生新时间戳版本,原版进 `_archive/`;
- 变更若推翻关键假设 → **必须回流 pd-eval 重验**(指出哪些指标卡失效),不许"改了就算了";
- 无既有产物可扫描时(项目刚起步),输出"尚无产物,直接落 ADR 即可",不编造影响面。
