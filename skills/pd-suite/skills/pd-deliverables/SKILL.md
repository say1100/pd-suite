# 交付文档产出

**须显式点名**(用户说"写 PRD/出汇报材料/生成评审文档"),仅讨论想法时不启动。

## 四种交付物

| 类型 | 场景 | 源材料 | 模板 |
|---|---|---|---|
| **PRD** | 交付研发/外部合作 | requirements + tradeoff + 产品定义卡 | templates 见 prompts/steps.md §W3 |
| **项目汇报** | 给老板/投资人/合作方 | 定义卡 + 路线图 + 评测报告 | templates.md §汇报(同上) |
| **评审材料** | 方案评审会 | tradeoff + feasibility 报告 | 同上 §评审 |
| **变更通报** | 变更后同步相关人 | change-impact + ADR | 同上 §通报 |

## 流程(步骤详见 prompts/steps.md §W1–W5)

1. **W1 定受众**:给谁看/用来做什么决策/时长限制——决定详略与口吻;
2. **W2 集材料**:只从 `outputs/` 既有产物取数,**文档中的每个数字必须标注来源产物**;
3. **W3 成文**:按模板组装;允许删繁就简,不允许发明新数据、新承诺;
4. **W4 自检**:数字与源一致、结论有出处、无"效果不错"式表述;
5. **W5 交付**:默认 Markdown;用户要 Word/PPT 时调用已装官方 docx/pptx 技能转换。

## 铁律

- **零新数据**:文档是资产的"视图",不是创作——发现材料缺关键信息,列"待补清单"而不是编;
- 执行摘要 ≤5 句;全文每个结论可回溯到某个产物文件;
- 竞品/市场数字必须带"检索日期与来源",过期数据标黄提醒。
