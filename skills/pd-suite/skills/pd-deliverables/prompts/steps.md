# 交付文档·分步指令

## W1 定受众(三问,答不出就问用户)
1. 给谁看?(决定术语深度:研发要细节/老板要结论/合作方要边界)
2. 用它做什么决策?(批准预算/排期/合作——文档结尾必须有明确的"请求事项")
3. 多长时间?(5 分钟汇报 ≠ 30 页 PRD)

## W2 集材料
1. 扫描 `outputs/` 列出可用产物,按类型对号入座(见 SKILL.md 表);
2. 缺什么列"待补清单"(如:无评测报告 → PRD 的"质量保障"节标待补);
3. **来源标注**:每个关键数字后括号注明产物文件名,如"正确率 85%(eval-plan v2)"。

## W3 成文模板

### §PRD(交付研发)
1. 背景与问题(引 requirements 痛点)→ 2. 目标与非目标(引定义卡"不做清单")→ 3. 用户与场景 → 4. 功能需求(F 清单,每条带验收口径)→ 5. 非功能需求(性能/安全,有则写)→ 6. 里程碑(引路线图)→ 7. 风险与依赖 → 8. 附录:口径库/评测集引用。

### §汇报(老板/投资人)
1. 一句话结论 → 2. 三个关键数字(带来源)→ 3. 做了什么/证明了什么 → 4. 下一步与需要的支持 → 附录备用。**先写请求事项,再写论证。**

### §评审材料
1. 评审对象与结论 → 2. 关键假设 TOP → 3. 待评审问题清单(逐条可投票)→ 4. 数据附录。

### §变更通报
1. 变更一句话 → 2. 影响(🔴🟡🟢分级)→ 3. 相关人各自要做什么 → 4. ADR 编号引用。

## W4 自检清单
□ 每个数字有来源 □ 无"效果不错"式模糊表述 □ 结论与源产物一致 □ 结尾有明确请求事项 □ 待补清单已列出

## W5 交付
- 默认 `.md` 落 `outputs/deliverables/`;
- 要 Word → 调用官方 docx 技能;要 PPT → 官方 pptx 技能;**转换前后内容必须逐字一致**,格式差异不算创作;
- 文件名:`<类型>-<主题>-<日期>.md`。
