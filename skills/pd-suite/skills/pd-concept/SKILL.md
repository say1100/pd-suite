# 方案构思与对比

输入:`outputs/requirements.md`(没有则先走 pd-requirements)。产物:`outputs/tradeoff-matrix.md`。

## 步骤(单步技能,指令内联)

1. **读 P0 需求**——它们是候选方案的硬性覆盖目标。
2. **生成 2–4 个候选方案**,方向上刻意拉开(如:自建 / 集成现成 / 最小人工+自动化混合),其中**必须含一个"最便宜验证方案"**(用最小成本先验证 P0 痛点是否真实,如人工跑一遍流程、单城市上线、纯手工服务)。
3. **trade-off 矩阵**,列固定:覆盖 P0 数(逐条对) / 验证周期 / 验证成本 / 技术风险(高中低+一句理由) / 可扩展性 / 依赖与单点。
4. **竞品位**:若有明确竞品,加一行"竞品现状"作对照基准;无竞品写"未调研",不编造。
5. **推荐 + 理由**:给出推荐方案和两条最关键理由;**只推荐不拍板**,最终选择记为用户决议,留 ADR 线索("为何选 A 不选 B")。

## 门禁

- 候选方案覆盖全部 P0 → 否则该方案标红 `⚠P0 缺口:REQ-xxx` 仍可保留,但推荐语必须提及;
- 只有一个候选方案 → 禁止交付,必须再拉出一个对照方案(哪怕明显更贵)——**没有对照的方案没有说服力**。

## 交接

推荐方案确定后:下一步走 pd-feasibility 可行性评审;评审 GO 后凭该方案进 pd-demo。
