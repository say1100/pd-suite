# Demo 设计·分步指令

## D1 页面清单
1. 从 requirements 的 P0 条目推导核心任务(每条 P0 至少映射一个任务)。
2. 页面清单 = 完成这些任务所需的最少页面集合;每页一行:页面名 + 一句话职责 + 服务的任务编号。
3. 砍页面比加页面难,所以先克制后补——初版清单之外想加页,须注明"阶段二可选"。

## D2 链路图
1. mermaid `flowchart`,节点=页面,边=跳转(标注触发条件,如"提交成功→")。
2. 逐条 P0 任务验证:从入口页出发存在完整路径覆盖该任务的全部步骤;不存在 → 补页面或补跳转,不许留"走到一半没路"的任务。
3. 产物存 `link-matrix.md`,内含:页面清单表 + mermaid 图 + 任务覆盖矩阵(任务 × 页面路径)。

## D3 四态矩阵
1. 表:页面 × 四列(正常态/空态/错误态/加载态),每格一句"看到什么 + 能做什么"。
2. 错误态必须写清:错误从哪来(网络/权限/输入非法)与用户下一步动作(重试/返回/求助)。
3. 空态是最常被漏的一列:首次使用、搜索无结果、列表为空,各写一句引导文案方向。
4. 行数必须 ≥ 页面数(check_demo_gate 会查);某页确实无数据列表可写"空态不适用+理由"。

## D5 打磨基线(design tokens)
1. 先定 5 件事再写页面:主色/辅助色/中性色阶、字号阶(≤4 档)、间距基数(4/8 网格)、圆角、按钮三态。
2. 可从 theme-factory 的预设主题选一套改,不自创配色。

## D6 生成代码
1. 单页演示 → 单 HTML 文件(内联 CSS/JS);多页面有状态 → web-artifacts-builder 的 React+Tailwind 脚手架。
2. 所有文案用真实语气的中文示例数据,禁止 lorem ipsum;"高级感"来自留白、字号层级和一致性,不靠装饰堆砌。
3. 视觉判断遵循 frontend-design 技能(已装):先定风格方向再动手,避免模板脸。

## D7 自检
1. 本地打开/构建,逐页截图与四态矩阵核对:每页四态是否都落实(至少正常态+错误态)。
2. 有 Playwright(webapp-testing)时:脚本走通每条 P0 任务路径并截图;无环境则人工点验并在交付说明里注明"未自动化验证"。

## D8 埋点清单(track-events.md)
1. 表:| 事件名 | 页面 | 触发交互 | 采集字段 | 服务哪个指标(占位,由 pd-eval 回填) |
2. 事件命名:对象_动作(如 resume_submit、paywall_view);字段至少含时间戳与用户标识占位。
3. 经验法则:每条 P0 任务的关键转化步骤至少 1 个事件;首访来源必埋。
4. **这份清单是 pd-eval 的开工凭证,不是可选项。**
