# 优先级方法速查

## MoSCoW(默认)

- **P0 / Must**:缺了产品不成立;判断标准:砍掉它,演示和首轮验证是否直接失败?
- **P1 / Should**:明显增值;砍掉后产品仍能验证核心假设。
- **P2 / Could**:观察项;仅当有人为它争论超过一轮才升 P1。

## KANO(用户点名时用)

把需求分五类:基本型(没有就骂)/ 期望型(越多越满意)/ 兴奋型(没有没人提,有了惊喜)/ 无差异 / 反向。
- P0 通常 = 基本型 + 少数期望型;兴奋型只挑一个进 P1 做差异化。
- 判定口诀:问"没有它会怎样"而不是"有它多好"。

## RICE(需求 ≥15 条时改用)

得分 = 触达 × 影响 × 置信 / 成本。四个量全部按团队约定的档位打分(如 1/2/3),**禁止拍绝对数**;得分排序后人工检一遍头尾,明显违和的标 `⚠依据待补` 回炉。

## 冲突处理

两条需求冲突(资源/逻辑上不可兼得)时:并排列出各自的"不做的代价",交用户拍板,**不要**替用户二选一;拍板结果记入产物"未决问题清单"的决议栏。
