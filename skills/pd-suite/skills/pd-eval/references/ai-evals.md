# AI 产品 evals 域(产品含大模型/算法能力时追加)

## 三件套

1. **离线评测集**:从真实用户输入抽样 + 最难 10%(bad case 偏置),规模起步 50–100 条,含预期行为标注;留出集永不参与 prompt/参数调整。
2. **LLM-as-judge**:判分维度拆开(正确性/完整性/语气各一问),judge prompt 给 1–2 个锚定样例;关键指标用人工抽检校准 judge(抽 20 条算一致率,≥80% 才可信)。
3. **回归评测**:prompt/模型/参数每次变更必跑全量评测集,与上一版对比;退步即回滚——评测集就是 AI 产品的"单元测试"。

## 指标对齐

- 任务成功率、格式合规率、拒答率、平均延迟 P50/P95、单次成本(token×单价)——全部进指标卡,与其他指标同规矩。
- **成本与延迟是产品指标**:给出预算上限(单次 ¥x / 秒 y),超限 = FAIL,和准确率同权重。

## 数据飞轮

- 线上 bad case 自动归档(用户点踩/人工抽检),每周人工归因:prompt 问题 → 改 prompt;能力问题 → 换模型/加工具;数据问题 → 进下一版数据集。
- bad case 经用户确认后进评测集(先人工复核再入库,防污染)。

## 安全红线(To B/涉未成年人必读)

- 输出安全策略(禁答类别)+ PII 不进日志/评测集;
- 上线前红队一轮:对抗输入/提示注入/越权诱导,结果记入 eval-report 附录。
